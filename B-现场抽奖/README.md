# 1024 现场抽奖

2026-10-23（周五）线下活动用的抽奖，在会场的一台电脑上单独跑。和"1024 猫咖"那个小游戏、店里的集章登记抽奖都不相干：奖品、记录、数据都是自己的。扭蛋机的动画、像素字和配色借猫咖的（`../A-像素猫咖/` 里的几个文件），所以要和猫咖放在同一个仓库目录里。

## 现场怎么抽

1. 工作人员先确认这个人满足条件（关注内源社区、猫猫观察局，加入猫猫群，或者参加了互动游戏……），系统不管这一步。
2. 工作人员点"抽一次"（或者按空格）。扭蛋机转一圈，扭蛋蹦出来、晃三下、裂开，当场出结果。
3. 抽到**一、二、三等奖**（虚拟奖品）：当场登记工号。登记好了，活动结束后组织方按工号统一联系兑奖。
4. 抽到**谢谢惠顾**：当场发一张猫猫图鉴卡。页面上写着还剩几张；发完了，就只是谢谢惠顾。

中了奖不登记工号，就抽不了下一次：免得人走了工号没留。真的登记不了（比如这个人不要了），点"作废"，这份奖品放回奖池。

同一个工号之前中过，登记时页面会提醒"W001 之前中过二等奖"，由工作人员决定：还是登记，或者作废这一次。

## 启动

要装 Node.js 18 以上（不用装任何别的包）。

```bash
cd B-现场抽奖
node server.js
```

浏览器打开它打印出来的地址（默认 `http://127.0.0.1:1025/`）。Windows 上也可以双击 `启动.bat`，macOS 上双击 `启动.command`。

| 页面 | 地址 | 给谁用 |
|---|---|---|
| 抽奖 | `/` | 现场：抽、登记工号、作废；浏览器全屏放着 |
| 设置 | `/admin.html` | 活动前配奖品和图鉴卡；活动中看记录、补货、暂停；活动后导出 |

只有这台电脑自己打得开（服务只听 `127.0.0.1`），所以不设口令。想让会场另一台电脑也打开设置页：`HOST=0.0.0.0 node server.js`，这时候同一个局域网里谁都能打开，自己掂量。

## 奖品

设置页里配，每一档：

| 项 | 意思 |
|---|---|
| 等级 | 一、二、三等奖，或者谢谢惠顾 |
| 名称 | 奖品本身，比如"定制机械键盘"（等级另外显示，不用写进名称） |
| 权重 | 抽到它的机会 = 它的权重 ÷ 还有库存的各档权重之和 |
| 库存 | 有几份；谢谢惠顾一般不限 |

库存抽完的那一档自动退出，剩下的照权重分。所有档都没库存了（没配谢谢惠顾、奖品又抽完了），点"抽一次"会说"奖池空了"，补货以后接着抽。

**猫猫图鉴卡**单独一个库存数。抽到谢谢惠顾、还有卡，就记一张"发了"；没卡了就不记。

**暂停**：设置页一个开关，暂停时抽奖页点不了"抽一次"。

## 数据和备份

- 都在 `data/lotto.json`（不进仓库）。每抽一次、每登记一个工号，都当场写进磁盘再回页面：页面上看到"一等奖"，记录就已经存好了。
- 每抽 20 次，`data/backups/` 里多存一份。
- 设置页的"清空重来"（彩排完用）：先把现在的存一份到 `data/backups/`，再清掉所有抽奖记录、把库存的"已发"归零；奖品设置留着。
- 活动结束：设置页"导出中奖名单"（工号、几等奖、奖品、时间，Excel 打开不乱码），交给兑奖的同事。

## 规则的细节

| 事 | 怎么处理 |
|---|---|
| 抽到什么 | 服务端用加密随机数按权重抽；页面只负责演动画 |
| 中了奖还没登记 | 不能抽下一次（`pending`），抽奖页一直停在登记那一步 |
| 工号的格式 | 字母、数字、`-`、`_`，2～32 位；去掉空格、转大写以后比较 |
| 同一个工号又中了 | 提醒，带上之前中的是第几次、几等奖；工作人员点"还是登记"才登记 |
| 登记错了 | 设置页的记录里能改工号 |
| 作废 | 只有中奖的能作废；放回库存，这一次记成"作废"，导出的中奖名单里没有它 |
| 认不出的等级 | 只有 0（谢谢惠顾）～3；别的不收 |
| 读 `lotto.json` 读坏了 | 服务起不来，不会当成空的接着写（那会把记录盖掉）；用 `data/backups/` 里最近的一份换回来 |

## 接口

都只在本机。失败回 `{err}`：`closed` 暂停中 · `pending` 有中奖还没登记（带 `no`）· `empty` 奖池空了 · `bad` 参数不对 · `dup` 这个工号中过（带 `prev`）· `none` 没有这一次 · `disk` 没存上。

| 接口 | 请求 | 返回 |
|---|---|---|
| `GET /api/state` | — | `{open, note, prizes, card, pending, recent}`：奖品带 `rest` 还剩几份 |
| `POST /api/draw` | — | `{draw}`：`{no, tier, name, card}` |
| `POST /api/claim` | `{no, emp, force}` | `{draw}`；同工号中过、没带 `force` 回 409 `dup` |
| `POST /api/void` | `{no}` | `{draw}` |
| `GET /api/draws` | — | 全部记录，最新的在前 |
| `POST /api/prize` | `{id?, tier, name, weight, stock}` | 没有 `id` 是新加，有是改；库存不能改得比已经发出去的少 |
| `POST /api/prize/del` | `{id}` | 只有一份都没发出去的能删 |
| `POST /api/restock` | `{id, n}` | 补 n 份 |
| `POST /api/settings` | `{open?, note?, cardStock?}` | 暂停开关、抽奖页上的一句提示、图鉴卡总数 |
| `POST /api/reset` | — | 先备份，再清空记录 |
| `GET /api/export?what=won｜all` | — | CSV |

## 代码

| 文件 | 做什么 |
|---|---|
| `core.js` | 规则：按权重从有库存的里抽、图鉴卡、登记、重复提醒、作废。不读写文件，有测试 `core.test.js` |

| `admin.html`、`admin.js` | 设置页 |
| `scene.js` | 扭蛋机那一幕（猫头扭蛋机、聚光灯、店猫） |
