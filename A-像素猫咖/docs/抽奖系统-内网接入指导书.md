# 抽奖系统 · 内网接入指导书

写给在内网接手的编码助理。抽奖系统的代码已经写完，在外网用假的 w3、假的 codehub 和稼先测通了。你要做的是：把它接上内网真的 w3、codehub、稼先，部署到内网服务器，在会场的两台电脑上实测。**活动在 2026-10-23（周五）**，线下部分不依赖你要接的任何东西，接不上也能办；线上部分要等你接通。

设计细节都在 [抽奖系统](抽奖系统.md)，本文只讲你要做的事和怎么判断做没做成。

## 一、背景

1024 线下 + 线上活动，宣传 Clowder AI 这个项目。活动配一套抽奖，做在"1024 猫咖"这个像素小游戏的同一个服务里，和店里原有的"集章登记抽奖"并行、互不相干。

**员工怎么拿到抽奖次数**（每一项加 1 次）：

| 来源 | 怎么发 |
|---|---|
| 关注内源社区、猫猫观察局，加入猫猫群 | 会场工作人员在后台手动加 |
| 参加现场互动游戏 | 工作人员手动加 |
| github star clowder-ai | 员工给工作人员看截图，工作人员手动加 |
| codehub star clowder-ai 仓库 | **自动**：员工登录后点"刷新"，服务端用服务账号查 |
| 关注稼先节目号 | **自动**：同上 |

自动的两种，同一个活动里每个工号只发一次；发了以后取消 star 也不收回。

**员工怎么抽**：

- **线下**：会场两台电脑。后台电脑上工作人员按工号加次数；前台电脑上员工输自己的工号（不输密码）、转扭蛋抽。
- **线上**：员工打开猫咖，走到一楼 1024 舞台右下角的扭蛋机，按 E。先用 w3 登录，之后按 R 刷新次数、按 E 抽。

线上线下是同一个奖池、同一份次数：同一个工号在会场抽的和在店里抽的算在一起。抽完由组织方按工号统一联系兑奖，系统里不记"已兑奖"。

**管理员**：w3 登录、工号在白名单里，或者用原来的后台口令。

## 二、已经做好的，不要重写

| 部分 | 文件 | 状态 |
|---|---|---|
| 规则：次数记账、自动来源去重、按库存和权重抽、活动状态 | `server/lotto-core.js` | 有测试 |
| 存盘和接口：管理员接口、用户接口、w3 会话、白名单 | `server/lotto.js` | 有测试 |
| w3 登录，按标准 OAuth2 授权码流程 | `server/w3.js` | 用假 w3 测通；**你要对上真 w3** |
| codehub、稼先的查询，地址和取值都可配置 | `server/lotto-sources.js` | 用假接口测通；**你要对上真接口** |
| 后台页面里的"现场抽奖"那一块 | `admin.html`、`js/admin-lotto.js` | 浏览器里走过 |
| 前台抽奖页 | `desk.html`、`js/desk.js`、`js/lotto-scene.js` | 浏览器里走过 |
| 店里的扭蛋机和特写 | `js/world-lotto.js`、`js/lotto-scene.js` | 浏览器里用假 w3 走过 |

所有配置都在数据目录（默认 `server/data/`）的 `lotto-config.json` 里。**没有这个文件时：没有 w3、没有自动发次数、后台只认口令**，店里的扭蛋机写"线上抽奖还没开"。也就是说，你接通之前，线下照样能用。

先跑一遍测试，确认拿到的代码是好的（Node 18 以上，没有任何依赖要装）：

```bash
cd A-像素猫咖
node --test 'server/*.test.js'
```

应该是 15 个全过。`server/lotto-w3.test.js` 会自己起一个假的 w3 和假的 codehub、稼先，再起真的服务端，从登录走到抽奖。你改了 `w3.js` 或 `lotto-sources.js` 以后，它还是要过：它测的是"按配置文件的写法能走通"。

## 三、你要做的事

按顺序做。每一步都写了"做成了是什么样"，没看到就不算做完。

### 1. 部署到内网服务器

按 [部署](部署.md) 的升级步骤，把这个分支的代码换上去。这次 `deploy.sh` 也改了：数据目录里多出 `lotto.json`、`lotto-config.json`，原来的脚本看到不认识的文件会拒绝启动。所以 `deploy.sh` 要和代码一起换。

**做成了**：

- 打开 `https://网站/1024-cat-cafe/admin.html`，用后台口令登录，最上面有"现场抽奖"一块。
- 打开 `https://网站/1024-cat-cafe/desk.html`，看得到扭蛋机，能用后台口令登录。
- 店里一楼舞台右下角、抓娃娃机左边，有一台小扭蛋机，走过去按 E，特写里写"线上抽奖还没开"。

### 2. 接 w3

**先问清楚这几样**（找 w3 的负责人，或者看 w3 的接入文档）：

| 要什么 | 填到 `lotto-config.json` 的 `w3` 里 |
|---|---|
| 授权页地址 | `authorize` |
| 拿 code 换 token 的地址 | `token` |
| 拿 token 取用户信息的地址 | `userinfo` |
| 注册应用拿到的 client id、client secret | `clientId`、`clientSecret` |
| 要申请的 scope（没有就不写） | `scope` |
| 回调地址，要在 w3 那边登记 | `redirect`，写 `https://网站/1024-cat-cafe/api/lotto/w3/callback` |
| 用户信息里哪个字段是工号（嵌套的写 `a.b`） | `empField` |
| 哪个字段是姓名（选填） | `nameField` |

完整的配置样子见 [抽奖系统](抽奖系统.md) 第四节。写好以后重启服务。

**w3 不是标准 OAuth2 的话**（比如是 CAS 票据、要签名、取到的是账号名要再换成工号），只改 `server/w3.js` 里的两个函数：

- `loginUrl(state)`：给回跳去 w3 登录的地址。`state` 要带过去，回来时原样带回到 callback 的 `state` 参数里。
- `identify(code)`：拿回调时地址上的 `code`（或者你们的票据，回调地址上叫什么就改成从那儿取），给回 `{emp: '工号', name: '姓名'}`，拿不到就抛错。

别的文件不用动：别处只认 `identify` 给回工号或者抛错。改完跑一遍测试；假 w3 是按标准 OAuth2 写的，如果你把协议改得完全不一样，就照着真 w3 的样子把 `server/lotto-w3.test.js` 里的 `mock()` 一起改掉，别删测试。

**做成了**：

1. 打开 `https://网站/1024-cat-cafe/api/lotto/me`，看到 `"w3":true`。
2. 在店里走到扭蛋机按 E，特写里写"用 w3 登录以后才能抽"；再按 E，跳去 w3，用你自己的账号登录。
3. 回到店里，左下角新闻里出"w3 登录好了"。再打开 `/api/lotto/me`，`me.emp` 是你的工号（大写、没有空格）。

没成的话，地址后面会带 `#lotto-err=…`，服务端日志里有原因，对照第五节查。

### 3. 白名单管理员

`lotto-config.json` 里 `admins` 写上管活动的同事的工号。**先别关口令**（`keyLogin` 不写，或者写 `true`）。

**做成了**：白名单里的人打开 `admin.html`，点"用 w3 登录"，回来只看得到"现场抽奖"那一块，能建活动、加次数；打开 `desk.html` 点"用 w3 登录"，直接到"输入你的工号"。不在白名单里的人登录以后，`admin.html` 写"不在抽奖后台的白名单里"。

需求里要求去掉口令。确认白名单里的人都能用 w3 进来以后，再把 `keyLogin` 改成 `false`、重启。关了以后，抽奖后台只认 w3 + 白名单；口令照样管名册、集章抽奖这些别的后台功能。

### 4. 接 codehub、稼先

**先问清楚**：用服务账号查"某个工号 star 了 clowder-ai 仓库没有"、"某个工号关注了稼先的那个节目号没有"，各是哪个接口、怎么鉴权、回来的 JSON 长什么样。

能直接按工号查的，只写配置（`lotto-config.json` 的 `sources`）：

| 字段 | 意思 |
|---|---|
| `url` | 地址，`{emp}` 会换成工号（会做 URL 编码） |
| `method` | 不写时有 `body` 就是 POST，没有就是 GET |
| `headers` | 鉴权头，比如 `{"Authorization": "Bearer 服务账号令牌"}` |
| `body` | POST 的内容，里面的 `{emp}` 也会换成工号 |
| `path` | 回来的 JSON 里哪个值说明"star 了"，嵌套写 `a.b` |
| `equals` | 写了就要相等才算；不写就是取到的值为真才算（空数组不算） |

接口形状对不上的话（要先换 token、要翻页、要按用户名不按工号查……），只改 `server/lotto-sources.js` 的 `check(src, emp)`：给回 `true` 或 `false`，查不了就抛错。查失败的，那一个来源给 0 次，提示"稍后再试"，不会多发。

**做成了**：

1. 找一个已经 star 了的同事（或者你自己先 star），在店里扭蛋机前按 R：特写里写"codehub star 各加了 1 次"。
2. 等 10 秒再按 R：写"没有新的次数"，次数不变。
3. 一个没 star 的工号按 R：不加次数，也不报错。
4. 把配置里的地址故意写错一个字母、重启、按 R：写"codehub star 没查成，稍后再试"，服务端日志里有"查 codehub 没成"。改回来。

### 5. 会场实测

用会场的两台办公电脑：

1. 后台电脑打开 `admin.html` 登录，建一个测试活动，配两档奖品（一档少量库存，一档"谢谢参与"不限），点"开始"，给一个工号加 2 次。
2. 前台电脑打开 `desk.html` 登录，输这个工号，看到"还有 2 次"，转两次。
3. 后台电脑上"抽奖记录"里看得到这两次，"导出中奖名单"能下载、Excel 打开不乱码。
4. 用手机或第三台电脑，在店里扭蛋机前用 w3 登录同一个工号：次数显示 0，和会场那边是同一份。
5. 测完把测试活动点"结束"（选"中止"），不要删数据目录。

**做成了**：五步都对上。

### 6. 活动前一天

- 后台建正式活动，配好每一档奖品的名称、等级、权重、库存。不配"谢谢参与"就是每次必中，那样大家抽的总次数不能多于奖品总数，不够了会碰到"奖池已空"，要补货。
- 点"开始"。
- 前台电脑登录好 `desk.html`，浏览器全屏。前台电脑旁边要有工作人员：前台电脑上存着登录状态，懂技术的人用开发者工具能拿到。
- w3 到周四还没接通：不写 `lotto-config.json` 的 `w3` 那一段，线上不开，线下照常。

## 四、改代码的规矩

- **改设计先改文档**：先改 [抽奖系统](抽奖系统.md)，再改代码。这个仓库一直这样做。
- **不加依赖**：服务端是零依赖的 Node，前端不打包。
- **照着周围的写法写**：中文注释、一行里写得比较紧凑，注释说"为什么"。
- **规则改了要有测试**：`server/lotto-core.js` 的任何改动，在 `server/lotto-core.test.js` 里加一条对应的测试。
- **不碰数据目录里的真数据**：测试用 `DATA_DIR=临时目录` 起服务。`lotto.json` 里是真的抽奖记录，不要删、不要手改。
- **秘密只放在 `lotto-config.json`**：client secret、服务账号令牌不能写进 `config.js`（那个文件会发给浏览器），也不能进仓库。
- **店里的扭蛋机不要加进图鉴**：图鉴三页全点亮是终极彩蛋的条件，加一样东西，已经集齐的猫会突然少一样。

## 五、出问题怎么查

| 看到的 | 原因 | 怎么办 |
|---|---|---|
| 登录回来地址带 `#lotto-err=state` | 回来时 cookie 里的 state 对不上：登录超过 10 分钟，或者 cookie 没带回来 | `redirect` 的域名、路径要和网站实际的一样；网站是 https 的话 `redirect` 也写 https |
| `#lotto-err=w3` | 换 token 或者取用户信息失败 | 服务端日志里"w3 登录没成："后面是 w3 回的原话 |
| `#lotto-err=emp` | 用户信息里取到的工号格式不对（工号只能是字母、数字、`-`、`_`，2～32 位） | 日志里"w3 给的工号格式不对"后面是取到的值；改 `empField`，或者在 `identify` 里把它转成工号 |
| 白名单里的人进不了后台 | `admins` 里的工号和 w3 给的不一样 | 打开 `/api/lotto/me` 看 `me.emp`，照着写进 `admins` |
| 按 R 一直"没查成" | 查询接口不通或者回的不是 JSON | 日志里"查 codehub 没成（工号）："后面是原因 |
| 服务起不来，日志里"lotto-config.json 读不了" | 配置文件不是合法的 JSON | 修好再起；写坏的配置不会被当成"没开" |
| `deploy.sh` 说数据目录里有不是猫咖的东西 | 换了代码没换 `deploy.sh` | 用这个分支的 `deploy.sh` |

## 六、还要领导确认的

下面几条先按左边做了，领导说不一样再改：

| 事 | 现在的做法 |
|---|---|
| 次数按活动算，还是按人终身算 | 按活动：活动结束剩下的作废 |
