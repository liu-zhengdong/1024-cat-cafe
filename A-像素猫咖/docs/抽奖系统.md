# 抽奖系统

2026-10-23（周五）线下 + 线上活动用的抽奖。需求出处：《抽奖系统 - 需求方案流程清单》（缅因猫/砚砚整理，2026-10-19）；本文是它落到猫咖里的第一版设计，写明已经定了的、还没定的和先后顺序。

**定位**：独立的一套，和"集章登记抽奖"（见[组织者后台](组织者后台.md)）并行，不替换。入口在店里的抽奖台；活动、奖池、次数、记录都是自己的，存在自己的文件里。身份是工号，不是猫：同一个工号在店里有几只猫、在会场的前台电脑上抽，都是同一个账户。

## 一、能做什么

| 能力 | 状态 | 说明 |
|---|---|---|
| 店里的抽奖台 | 设计内（做完，等 w3） | 一楼舞台右下角、抓娃娃机左边一台小扭蛋机，走过去按 E 切到特写（`js/world-lotto.js`）；E 转一下，R 刷新次数。没开 w3 时特写里写"线上抽奖还没开" |
| w3 认证登录 | 设计内，**依赖外部** | 线上抽奖必须有它：没有 w3 就不知道屏幕前的人是不是这个工号，谁都能输别人的工号把次数抽光。**w3 周五前没接好，线上抽奖关掉，不退回手输工号** |
| 前台电脑代抽 | 设计内 | 管理员登录的前台电脑上，用户输自己的工号（不输密码），在这台电脑上抽 |
| 后台加次数 | 设计内 | 按工号加，选一个原因（关注进群、互动游戏、github star 截图……），可以写一句备注 |
| codehub star、稼先关注自动发次数 | 设计内，**依赖外部** | 用户点"刷新"时服务端用服务账号查；接口拿不到就退回管理员手动加 |
| github star 自动发次数 | 显式不做（周五） | 先由管理员看截图手动加；以后再做用户 OAuth |
| 活动和奖池 | 设计内 | 一个活动一个奖池；奖品有等级、权重、库存；补货；暂停 |
| 后台查记录、导出中奖名单 | 设计内 | 按等级、工号筛；按活动导出 CSV（Excel 直接打开） |
| 用户看自己的记录 | 设计内 | w3 登录后看自己抽到过什么；看不到兑奖状态 |
| 兑奖 | 显式不做 | 在系统外用导出的表管理，系统里不标"已兑奖" |
| 白名单管理员 | 设计内（做完，等 w3） | w3 登录 + 白名单工号；口令可以留着也可以关（见"关键决策"第 5 条） |

## 二、关键决策

1. **做在猫咖同一个服务里，数据另存一个文件 `lotto.json`**。理由：抽奖台在店里，后台框架、部署、备份都现成；另存一个文件，是让它和集章抽奖、名册互不牵扯，以后单独清掉也不碰猫。
2. **抽到什么先写进磁盘，再回给用户**。名册是攒 200 毫秒一起写的；抽奖不能这样：回了"一等奖"、进程这时候挂了，记录就没了。抽奖、加次数、补货、改活动状态都当场写完再回。
3. **一次抽奖是一段同步代码**：查活动状态和时间、查剩几次、从有库存的奖品里按权重抽、扣库存、记一笔，中间没有 `await`。Node 一个进程里不会有两次抽奖交错，不用锁。
4. **次数不存一个数，存一笔笔发放**：剩几次 = 这个活动里发给这个工号的次数之和 − 抽过的次数。谁、什么时候、为什么发的都查得到；自动来源靠"同一个活动、同一个工号、同一个来源只有一笔"去重。
5. **后台鉴权**：w3 + 白名单工号，或者后台口令。白名单写在数据目录的 `lotto-config.json` 的 `admins` 里，只有部署的人改得了；不放进 `config.js`（那份会发给浏览器）。`keyLogin:false` 关掉口令以后，抽奖后台只认 w3 + 白名单（需求里要求去掉口令；w3 没验通之前别关，关了就进不去）。用 w3 进后台页面的，只看得到"现场抽奖"那一块，名册、集章抽奖这些还是要口令。
6. **前台电脑用一张单独的"前台抽奖"页，不走地图**。需求里写的是在前台电脑上按 E 抽；但每来一个人都要在地图里走到抽奖台，现场排队会慢。前台页面用店里同一套像素字、窗框和扭蛋机：输工号 → 显示"张*三，还有 2 次" → 转扭蛋 → 出结果。和地图里抽用的是同一个接口、同一个奖池。页面是 `desk.html`（`js/desk.js`）：
   - 工作人员用后台口令登录一次，存在这个标签页里，和后台页面分开存：在这个标签页里改地址打开 `admin.html`，还要再输一次口令。前台电脑上的人懂技术的话仍然拿得到口令（开发者工具），所以前台电脑要有人看着；w3 + 白名单以后也一样。
   - 抽到什么是服务端定的：按"转"就去抽，扭蛋晃着等结果，结果回来才裂开。扭蛋的颜色跟着几等奖走（一等奖金黄，没中是紫的）。
   - 抽完、或者 30 秒没人碰，回到"输工号"：下一个人看不到上一个人的工号和结果。
7. **工号按大写、去掉空格以后比较**，和集章登记一样（`Account.empKey`）。
8. **w3 按标准 OAuth2 授权码流程写，内网不一样只改一个文件**。`server/w3.js` 跳去 authorize → 回到 `/api/lotto/w3/callback` → code 换 token → token 取用户信息 → 按 `empField` 读出工号；地址、client、字段都写在 `lotto-config.json` 的 `w3` 里。w3 实际是 CAS、要签名、或者工号要另外查，只改 `loginUrl()` 和 `identify()`，别处只认"给回 `{emp}` 或者抛错"。回来时 `state` 要和发出去的、cookie 里的都对上（防别人塞自己的 code 进来）；会话是一张随机令牌放在 HttpOnly cookie 里，库里只存散列，12 小时。
9. **codehub、稼先的查询写成可配置的 HTTP 调用**（`server/lotto-sources.js`）：地址里 `{emp}` 换成工号，回来的 JSON 按 `path` 取值、可以要求 `equals`。接口形状对不上（要先换 token、要按用户名查……）只改 `check()`。查失败一律算 0 次、提示稍后再试；同一个工号 10 秒内只能刷新一次，免得把外面的接口刷爆。
10. **店里的抽奖台不进图鉴、不算"店里的 119 样东西"**：图鉴三页点亮是终极彩蛋（全成就）的条件，加一样东西会让已经集齐的猫突然少一样。活动结束删掉 `js/world-lotto.js` 那两行加载就撤了。别的猫不来抽（抽奖是人的事）。

## 三、数据

`lotto.json`：

```
acts:   [{id, name, status, start, end, endWhy, prizes:[{id, tier, name, weight, stock, given}]}]
grants: [{act, emp, src, n, by, why, t}]
draws:  [{act, emp, prize, tier, name, via, by, t}]
```

| 字段 | 取值 | 认不出的取值怎么办 |
|---|---|---|
| `status` | `draft` 草稿 · `live` 进行中 · `paused` 暂停 · `ended` 结束 | 读库时认不出的当 `paused`（不让抽，后台看得见、能改） |
| 状态怎么变 | `draft→live`、`live⇄paused`、`live/paused→ended`；`ended` 不能再变 | 别的变法拒绝 |
| `endWhy` | `done` 到期 · `early` 提前结束 · `abort` 中止 | 只是记一笔原因，三种行为一样：不能再抽、记录留着 |
| `start` / `end` | 时间戳，可以空着 | 不在时间里的不能抽；`end` 到了以后状态自己当作 `ended`（`done`） |
| `stock` | 非负整数，或者 `null` 不限 | 不限的用来配"谢谢参与" |
| `weight` | 正数 | 不是正数的奖品不进抽奖 |
| `src` | `manual` 管理员加 · `codehub` · `jiaxian` 稼先 · `github` | 别的拒绝。`manual` 可以加也可以减（减到不少于已经抽掉的）；其余三种每个活动每个工号只发一笔 1 次 |
| `via` | `w3` 自己登录抽 · `desk` 前台代抽 | — |

**抽**：从 `weight>0`、还有库存的奖品里按权重抽（库存 0 的退出，剩下的权重自然归一）。一个能抽的都没有：不扣次数，回"奖池已空"。必中还是可能不中，看组织者配没配"谢谢参与"这一档：不配就是必中，那么大家抽的总次数要不多于奖品总数，不够了就会碰到"奖池已空"，要补货。

## 四、接口

管理员接口挂在后台下面，带后台口令（请求头 `X-Admin-Key`，和[组织者后台](组织者后台.md)一样，输错 10 次先歇一会儿）；w3 接好以后换成 w3 + 白名单。代码在 `server/lotto.js`，后台页面那一块在 `js/admin-lotto.js`。

| 接口 | 请求 | 返回 |
|---|---|---|
| `GET /api/admin/lotto/state` | — | `{acts:[活动，带此刻的 status、每个奖品的 rest、draws 抽了几次、people 几个工号有过次数], current}`；`current` 是进行中的活动（有好几个取最后建的） |
| `POST /api/admin/lotto/act` | `{name, start?, end?}` | `{act}`：新活动，草稿 |
| `POST /api/admin/lotto/act/status` | `{id, to, why?}` | `{act}`；`to` 是 `ended` 时 `why` 是 `early` 或 `abort` |
| `POST /api/admin/lotto/prize` | `{act, tier, name, weight, stock}` | `{prize}`；`stock` 是 `null` 就是不限 |
| `POST /api/admin/lotto/prize/edit` | `{act, id, tier?, name?, weight?, stock?}` | `{prize}`；库存不能少于已经抽出去的 |
| `POST /api/admin/lotto/restock` | `{act, id, n}` | `{prize}` |
| `GET /api/admin/lotto/emp?emp=&act=` | — | `{emp, left, grants, draws}`；不带 `act` 就是进行中的那个 |
| `POST /api/admin/lotto/grant` | `{act, emp, n, why}` | `{grant, left}`；`src` 固定是 `manual`，`n` 是负数就是减 |
| `POST /api/admin/lotto/draw` | `{emp, act?}` | `{draw, left}`：前台代抽 |
| `GET /api/admin/lotto/draws?act=&tier=&emp=` | — | `{draws, total}`：最新的在前，最多 500 条 |
| `GET /api/admin/lotto/export?act=&all=1` | — | CSV：工号、几等奖、奖品、抽奖时间、怎么抽的；不带 `all` 只有中了的 |

用户那一侧（`/api/lotto/*`，w3 会话放在 cookie `lotto_sid` 里，不用另带请求头）：

| 接口 | 返回 |
|---|---|
| `GET /api/lotto/me` | `{w3 开没开, sources 配了哪几个来源, act 进行中的活动, me}`；`me` 没登录是 `null`，登录了是 `{emp, name, admin 在不在白名单, left, draws, got:{codehub, jiaxian 这个活动里发过没有}}` |
| `GET /api/lotto/w3/login?back=shop｜desk｜admin` | 302 去 w3；登录完回到 `back` 那一页，地址后面带 `#lotto=in` 或 `#lotto-err=state｜w3｜emp｜disk` |
| `GET /api/lotto/w3/callback?code=&state=` | w3 回来的地方（写进 `lotto-config.json` 的 `redirect`，也要在 w3 那边登记） |
| `POST /api/lotto/refresh` | `{left, got, no, fail}`：这次发了的、查了没有的、没查成的；10 秒内再来回 429 `{err:'soon', wait}` |
| `POST /api/lotto/draw` | `{draw, left}`，`via` 是 `w3` |
| `POST /api/lotto/logout` | 会话作废 |

失败回 `{err}`：`act` 活动不在进行中 · `time` 不在活动时间里 · `none` 次数不够 · `empty` 奖池空了 · `bad` 参数不对（400）· `disk` 没存上（500，内存也退回去了）。

`lotto-config.json`（数据目录里，改完重启；没有这个文件就是没开 w3、没有自动发次数、后台只认口令）：

```json
{
  "w3": {"authorize": "https://w3…/authorize", "token": "https://w3…/token", "userinfo": "https://w3…/userinfo",
         "clientId": "…", "clientSecret": "…", "scope": "openid",
         "redirect": "https://网站/1024-cat-cafe/api/lotto/w3/callback", "empField": "工号在用户信息里的字段，可以写 a.b", "nameField": "选填"},
  "admins": ["工号", "…"],
  "keyLogin": true,
  "sources": {
    "codehub": {"url": "https://…?user={emp}", "headers": {"Authorization": "Bearer …"}, "path": "data.starred", "equals": true},
    "jiaxian": {"url": "https://…", "method": "POST", "body": {"emp": "{emp}"}, "path": "list"}
  }
}
```

里面有 client secret 和服务账号的令牌：`backup` 会把它一起打包，备份文件别外传。

## 五、还没定的

| 事 | 先这么做 | 等谁 |
|---|---|---|
| 次数按活动算还是按人终身算 | 按活动：活动结束剩下的作废，下一个活动重新发 | 领导确认（周五只有一个活动，两种结果一样） |

| 项 | 通过条件 | 不通过怎么办 |
|---|---|---|

## 七、先后顺序

| 批 | 做什么 | 怎么算做完 |
|---|---|---|
| 1 | 次数、按库存抽、活动状态的纯逻辑（`server/lotto-core.js`） | 测试覆盖：去重、减次数的下限、库存抽完、状态变化、认不出的取值 |
| 2 | 存盘、管理员接口（先用后台口令）、后台页面加"抽奖"一块 | 本机建活动、配奖品、给工号加次数、导出 CSV，重启以后数据还在 |
| 3 | 前台抽奖页 | 两台电脑：一台加次数，另一台输工号抽到，后台看得到 |
| 4 | w3 登录、店里的抽奖台、用户看自己的记录 | 真账号登录、在店里抽到；拿不到 w3 就跳过这批，线上不开 |
| 5 | codehub、稼先自动发次数 | 真工号刷新以后次数加 1，再刷新不再加 |

**进度**（2026-10-19，第二次）：批 4、5 里不依赖内网的部分也做完了：w3 登录（标准 OAuth2）、会话、白名单后台、用户接口、codehub / 稼先的可配置查询、店里的抽奖台和特写、后台页面和前台页面的"用 w3 登录"。用一个假的 w3 和假的 codehub、稼先走通（`server/lotto-w3.test.js`，浏览器里也走过店里那一段）。剩下的是内网的事：真 w3 的地址和协议、真 codehub / 稼先的接口、真账号实测，见[内网接入指导书](抽奖系统-内网接入指导书.md)。

**进度**（2026-10-19）：批 1～3 做完，本机验证过：规则 13 个测试；接口走通（加次数、抽、导出、重启后数据还在）；后台页面和前台页面在浏览器里走通（查次数、两次抽奖、没有次数、窄屏）；120 个并发抽奖抢 10 个奖品，正好发出 10 个，其余回"奖池空了"、不扣次数。还没在两台真电脑上走过。

批 1～3 不依赖任何外部系统，周五线下靠它们就能办；4、5 看外部什么时候到位。
